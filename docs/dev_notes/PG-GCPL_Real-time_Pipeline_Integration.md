│     - 低秩矩阵U: FP32 → FP16                                             │
│     - 解码器MLP: 保持FP32 (仅7K参数,可忽略)                                │
│     输出: model_quantized.bin (~10 KB + 7K MLP = 38 KB)                 │
│     ✓ 存储: 38 KB vs 传统38.88 MB (1000× 压缩)                           │
└─────────────────────────────────────────────────────────────────────────┘
                                   │
                                   ▼
┌────────────────────────────────────────────────────────────────────────┐
│                      实时渲染阶段 (Runtime)                              │
└────────────────────────────────────────────────────────────────────────┘
                                   │
                                   ▼
┌─────────────────────────────────────────────────────────────────────────┐
│  4. 运行时解压查询 (Runtime Decompression Query)                          │
│     输入: (shading_point, light_params_5D)                               │
│     │                                                                     │
│     ├─▶ 4a. 物理基函数计算 (Physics Basis, CPU/GPU)                       │
│     │    - 从5D参数计算7D物理基 Φ(θ,φ,I,T,c)                              │
│     │    - 时间复杂度: O(7) SIMD计算                                       │
│     │    - 延迟: ~0.001ms                                                 │
│     │                                                                     │
│     ├─▶ 4b. 高斯混合查询 (Gaussian Mixture Query, GPU)                    │
│     │    - 找最近K'个高斯 (K'=3, top-k加速)                                │
│     │    - 计算高斯权重 w_j = exp(-0.5 * dist²)                           │
│     │    - 时间复杂度: O(K') ≈ O(1) (K'固定)                              │
│     │    - 延迟: ~0.02ms (GPU并行)                                        │
│     │                                                                     │
│     ├─▶ 4c. 低秩SH重建 (Low-Rank SH Reconstruction, GPU)                 │
│     │    - SH_j = U_j @ (coeffs_j @ Φ_physics)                           │
│     │    - 矩阵乘法: [27×8] @ ([8×7] @ [7×1]) = [27×1]                   │
│     │    - 时间复杂度: O(27×8×7) = O(1512) FLOPs                          │
│     │    - 延迟: ~0.05ms (GPU融合kernel)                                  │
│     │                                                                     │
│     ├─▶ 4d. 高斯加权聚合 (Gaussian Weighted Sum, GPU)                     │
│     │    - SH_total = Σ w_j × SH_j                                        │
│     │    - 时间复杂度: O(K' × 27) = O(81)                                 │
│     │    - 延迟: ~0.01ms                                                  │
│     │                                                                     │
│     └─▶ 4e. SH评估 (SH Evaluation, GPU)                                  │
│          - 与传统方法相同,计算最终辐射度                                     │
│          - 时间复杂度: O(27)                                              │
│          - 延迟: ~0.01ms                                                 │
│                                                                          │
│     输出: radiance (RGB)                                                 │
│     总延迟: ~0.1-0.15ms (GPU, 无Cache)                                   │
│              ~0.03-0.05ms (GPU, Cache命中70%)                            │
│                                                                          │
│     ✓ 优势对比传统方法:                                                    │
│       - 延迟: 0.15ms vs 0.2-0.5ms (1.3-3.3× faster)                     │
│       - 内存: 38 KB vs 38.88 MB (1000× smaller)                         │
│       - 可编辑: 支持任意5D参数实时调整                                      │
└─────────────────────────────────────────────────────────────────────────┘
                                   │
                                   ▼
┌─────────────────────────────────────────────────────────────────────────┐
│  5. 可选: Temporal LRU Cache (进一步加速)                                 │
│     - 缓存最近查询的K'个高斯组合结果                                         │
│     - 缓存大小: 1024个条目 (可配置)                                         │
│     - 命中率: 70-80% (游戏场景典型值)                                       │
│     - Cache命中时延迟: ~0.03ms                                            │
│     输出: radiance (RGB, cached)                                         │
└─────────────────────────────────────────────────────────────────────────┘
                                   │
                                   ▼
┌─────────────────────────────────────────────────────────────────────────┐
│  6. 着色与合成 (Shading & Compositing)                                   │
│     - 与传统方法相同                                                       │
└─────────────────────────────────────────────────────────────────────────┘


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
核心改进:

### 4.3 替代测试方案设计

#### 方案A: 独立性能基准测试 (Standalone Micro-Benchmark) ✅ **推荐**

**核心思路**: 隔离PG-GCPL解压kernel,独立测试GPU性能

```python
# benchmark_decompression_latency.py

import torch
import time
from PG-GCPL.src.models.gaussian_physics_5D import GaussianPhysicsCompression5D

def benchmark_single_query_latency(model, num_queries=10000):
    """测试单次查询延迟 (GPU)"""
    model.eval().cuda()

    # 预热GPU
    for _ in range(100):
        _ = model.query_random_point()

    torch.cuda.synchronize()

    # 测试延迟
    latencies = []
    for _ in range(num_queries):
        start = time.perf_counter()

        # 模拟运行时查询
        probe_pos = torch.rand(1, 3).cuda()  # 随机空间位置
        light_params = torch.rand(1, 5).cuda()  # 随机5D参数

        # 解压: 物理基 + 高斯查询 + 低秩重建
        sh_coeffs = model(probe_pos, light_params)

        torch.cuda.synchronize()
        end = time.perf_counter()

        latencies.append((end - start) * 1000)  # ms

    return {
        'mean_latency': np.mean(latencies),
        'p50_latency': np.percentile(latencies, 50),
        'p95_latency': np.percentile(latencies, 95),
        'p99_latency': np.percentile(latencies, 99),
        'throughput_qps': 1000 / np.mean(latencies)
    }


def benchmark_batched_query_throughput(model, batch_sizes=[1, 16, 64, 256]):
    """测试批量查询吞吐量 (GPU)"""
    results = {}

    for batch_size in batch_sizes:
        probe_pos = torch.rand(batch_size, 3).cuda()
        light_params = torch.rand(batch_size, 5).cuda()

        # 预热
        for _ in range(10):
            _ = model(probe_pos, light_params)

        torch.cuda.synchronize()
        start = time.perf_counter()

        # 测试吞吐量
        num_iterations = 1000
        for _ in range(num_iterations):
            _ = model(probe_pos, light_params)

        torch.cuda.synchronize()
        end = time.perf_counter()

        total_queries = batch_size * num_iterations
        elapsed = end - start
        throughput = total_queries / elapsed

        results[f'batch_{batch_size}'] = {
            'throughput_qps': throughput,
            'latency_per_query': 1000 / throughput  # ms
        }

    return results


# 性能目标验证
targets = {
    'p95_latency': 0.5,      # ms (保守目标)
    'p99_latency': 1.0,      # ms
    'throughput': 10000,     # QPS
}

# 运行基准测试
results = benchmark_single_query_latency(model, num_queries=10000)

# 检查是否达标
for metric, target in targets.items():
    actual = results[metric]
    status = "✓ PASS" if actual <= target else "✗ FAIL"
    print(f"{metric}: {actual:.3f} ms (target: {target:.3f}) {status}")
```

**优势**:
- ✅ 完全GPU测试,无Mitsuba依赖
- ✅ 精确控制测试条件(batch size, 查询数)
- ✅ 测量纯解压延迟,无其他管线开销
- ✅ 快速迭代,优化CUDA kernel后立即验证

- PG-GCPL的实时性能优势来自**压缩模型本身**,而非Mitsuba
- 解压是纯GPU计算(物理基+矩阵乘法),延迟可独立测量
- 当前0.145ms (CPU)已达标,GPU优化后预期<0.1ms
